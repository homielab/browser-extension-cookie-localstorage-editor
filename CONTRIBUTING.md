# Contributing

Thanks for taking a look. Bug reports and small fixes are very welcome.

## Reporting a bug

Please include the browser and version, the page you were on (host only is
fine), what you did, and what happened instead. A screenshot of the popup helps
a lot.

## Getting set up

The extension is the files in `src/` and runs unbuilt; the build only minifies
for release. Load `src/` unpacked as described in the [README](README.md#installing).

```
npm install           # dev tools: jsdom, esbuild, fflate, ESLint, Prettier
npm test              # unit tests, plus the popup's DOM tests in jsdom
npm run lint          # ESLint, then Prettier in check mode
npm run test:dist     # builds dist/ and reruns the DOM tests on the minified popup
```

`npm run lint:fix` applies every automatic fix and `npm run format` only
reformats. Prettier owns the layout (`.prettierrc.json`: 120 columns, double
quotes); ESLint (`eslint.config.mjs`) checks the code and leaves layout alone.

Before opening a pull request, run all three checks and try the change in a
browser. A change to the cookie logic is worth checking against a real page:
an attribute the browser will not accept should surface the browser's own
error rather than fail silently.

## Where things live

```
src/                      everything that ships, and nothing else
  manifest.json
  popup/popup.html        markup and the row, editor and panel templates
  popup/popup.css         all styling, light and dark
  popup/popup.js          header, tabs, notices and the Cookies tab
  popup/storage-view.js   the Local storage tab
  access/                 the window that asks for host access
  lib/cookies.js          pure cookie logic: no DOM, no extension APIs
  lib/storage.js          pure local storage logic, likewise
  lib/api.js              thin wrapper over the WebExtension APIs
  icons/                  generated by tools/make-icons.py
test/                     unit tests (cookies, storage) and DOM tests (popup)
tools/                    build, icon and screenshot scripts
store/                    Web Store listing copy and images
```

The awkward parts belong in `lib/cookies.js` and `lib/storage.js`, which hold no
references to the DOM or the browser and are tested directly. `lib/api.js`
prefers Firefox's `browser` namespace and falls back to `chrome`, so the same
code runs in both.

`test/popup.test.js` drives the real popup in jsdom against a mock cookie store
that follows the browser's rules (suffix matching, path scoping, `Secure`
schemes, public suffixes) and a mock page whose `localStorage` has a quota.

## Rules the code depends on

- **Never build markup from cookie or storage data with `innerHTML`.** A hostile
  page can set those values. Use `textContent` or the templates.
- **Never request permissions from the popup.** Called there,
  `permissions.request()` can open the browser's dialog _behind_ the popup,
  where nobody sees it. The popup opens `access/access.html` in a focused
  window instead, and the prompt comes from there.
- **Functions injected into pages must be self-contained.** `lib/api.js` passes
  them to `scripting.executeScript`, which serialises them, so they cannot use
  anything outside their own body.
- **A refresh that finds no change must not rebuild the list.** Rebuilding
  discards the DOM under the user's pointer and selection.
- **The popup's height comes from its content.** The browser sizes the popup
  from the document, so tying the document to the viewport collapses it. The
  list caps itself instead (360px, or 140px while the import/export panel is
  open) and scrolls.
- **No dependencies in shipped code.** The extension must run from `src/` as is,
  with nothing fetched at runtime. The build may only shrink files, never change
  what they do; `npm run test:dist` holds it to that.

Comments should explain _why_, not restate the code.

## Releasing

1. Bump `version` in `src/manifest.json` and `package.json` (the build checks
   they match), and move `[Unreleased]` in `CHANGELOG.md` under the new version.
2. `npm run test:dist`. The build writes `dist/<name>-<version>/` (loadable
   unpacked, to try the exact build) and the `.zip` to upload. It stops if the
   manifest breaks a store rule, a referenced file is missing, or the package
   goes over 2 MiB; the zip is reproducible. `--no-minify` helps debug it.
3. Upload the zip to the Chrome Web Store; listing copy, permission
   justifications and images are in [store/](store/README.md).

After a UI change, regenerate the store images: `npm run icons` redraws the
icons and promo tiles, and `npm run screenshots -- <captures-dir> <out-dir>`
frames popup captures as 1280x800 screenshots. Both need Pillow
(`python3 -m pip install pillow`).
